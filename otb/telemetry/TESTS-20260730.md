# Recette du 30 juillet 2026

## Périmètre

Les trois équipements OpenWrt actifs ont été contrôlés séquentiellement : R4
Sud, switch cœur, puis R4 Pro. Aucun flash, redémarrage d'équipement ou
changement réseau n'a été nécessaire. Un backup ciblé et un script de rollback
ont été créés sur chaque équipement avant copie des fichiers.

Toutes les cibles utilisaient OpenWrt SNAPSHOT, Linux 6.18.39 et APK v3. Les
dépendances `luci-base`, `rpcd-mod-ucode`, `ucode-mod-fs`, `ethtool-full`,
`luci-theme-argon` et `luci-i18n-base-fr` étaient présentes.

## Validation du code

- `sh -n` : scripts init, enregistreur et installateur valides ;
- `node --check` : vue LuCI valide ;
- JSON : menu et ACL valides ;
- `ucode -c -s` puis chargement du bytecode : OK sur les trois cibles ;
- tests de schéma : seuils, marges, drapeaux DDM, PWM et fréquence cohérents ;
- SHA-256 de l'archive pilote :
  `3f5ae24a4fa6ab3b91313cb41e237cfb2cd8ed3d8c0f8f12329371d292627853`.

marge thermique la plus faible observée.

## Coût mesuré

| Cible | Appel `status` complet | Appel `sample` | RSS de l'enregistreur |
|---|---:|---:|---:|
| R4 Pro | ~0,14 s | ~0,02 s | ~1,35 Mio |
| R4 Sud | ~0,12 s | ~0,01 s | ~1,36 Mio |
| Switch cœur | ~1,14 s | ~0,04 s | ~1,46 Mio |

`status` lit les EEPROM/DDM avec `ethtool`; le switch vérifie jusqu'à huit ports,
d'où son temps supérieur. `sample`, exécuté toutes les cinq minutes, utilise les
capteurs sysfs et ne lance pas ces huit lectures DDM.

L'empreinte persistante est inférieure à 40 Kio hors métadonnées du paquet.
L'historique occupait 4 Kio pendant la recette et reste plafonné à 288 lignes.

## Non-régression réseau

Les SHA-256 de `/etc/config/network`, `/etc/config/wireless` et
`/etc/config/firewall` sont restés strictement identiques avant/après sur les
trois équipements.

- R4 Pro : deux membres 10G (`mxl_lan5`, `eth1`) UP, même agrégateur ;
- R4 Sud : deux membres 10G (`sfp-lan`, `sfp-wan`) UP, même agrégateur ;
- switch : LACP Pro sur `lan1`+`lan2`, LACP Sud sur `lan3`+`lan4`, tous à 10G ;
- les VLAN effectifs et les routes sont restés inchangés ;
- les trois groupes MLO du Pro et du Sud sont restés présents ;
- le canal 2,4 GHz est resté sur 11 ;
- les trois WAN du Pro étaient en ligne dans `mwan3` ;
- ping Internet : 0 % de perte sur l'essai final et résolution DNS fonctionnelle ;
- `otb-wan-heal` est resté activé et actif ;
- Home Assistant, Mosquitto et Zigbee2MQTT sont restés actifs sur le R4 Sud.

Le contrôle final de `/srv` sur le R4 Sud indiquait 5,6 Gio utilisés sur
6,9 Gio, soit **80 %**, avec environ 1,4 Gio disponibles. Ce point ne résulte
pas du module de télémétrie, mais constitue un risque d'exploitation à
surveiller pour Home Assistant et ses journaux.

## LuCI

La ressource JavaScript servie par les trois équipements a le même SHA-256. Le
thème Argon et la langue française sont actifs sur les trois cibles. Une session
LuCI réelle sur le R4 Pro a confirmé :

- présence du menu « Télémétrie matérielle » ;
- rendu des cartes, tableaux, seuils et historique ;
- rafraîchissement périodique encore fonctionnel après un cycle complet de
  30 secondes ;
- aucune erreur ni alerte JavaScript dans la console du navigateur.
